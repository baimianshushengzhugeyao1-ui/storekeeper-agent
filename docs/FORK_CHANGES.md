# 二开范围与关键取舍

## 缺号追问
原流程无法执行缺订单号的单个取消任务，会转人工。新增澄清节点复用原有 interrupt 和检查点，在接口、命令行与网页上接收订单号；不重新分类，保留意图和任务编号。补充信息不是审批，后续仍需规则与人工授权。

## 执行回执
取消接口得到异步 job 编号只能证明受理。新增 submitted 结果和未验证结算标识，保存 job 元信息并按结构化状态构造回复。没有增加实际完成轮询，不因 done 标志单独确认款项到账。

## 输入与并发
补号校验格式、字段白名单、工单状态和暂停点归属。接口与图节点各有防线，进程内锁协调检查与恢复；不夸大为分布式幂等。

## 评测
新增真实 DeepSeek 接入、模拟订单预览、冻结测试样本和检索证据级评分。自建合成数据不代表线上用户效果；检索基线沿用原模型和 Top3，不作为原创检索算法或优化提升。

## 来源
订单核验、审批机制、LangGraph 持久化、基础前后端和原 Chroma 检索来自上游。扩展由 Codex 协助完成；简历与面试应根据本人能够解释、运行和复测的部分说明贡献。
